## 4. 남은 관찰 사항 (미해결)
- capacity 시나리오에서 **다른 Godot 프로세스가 시작되는 순간** 특정 봇의 입력이 150~350ms 동안 서버에 도착하지 않는 현상. 클라이언트는 정상 전송 중(로그 확인), 모든 프로세스 실행이 끝난 뒤에는 발생하지 않음. 단일 PC에 프로세스 10개를 띄우는 테스트 환경 특성으로 추정되나 **실기기 분산 테스트로 재확인 필요**. 이 경우에도 서버 외삽 + 클라이언트 보정으로 최대 오차 0.85m 내에서 복구됨.

## 5. 향후 테스트 계획
- Phase 3: 모바일 터치 입력 단위 테스트, Android 실기기 2대 + PC 혼합 접속
- 지연/손실 시뮬레이션: clumsy(Windows) 등으로 100~200ms 지연, 2~5% 손실 환경에서 보정 지표 측정
- 부하: 방 프로세스 N개 동시 실행 시 서버 CPU/메모리 측정
- 보안: 미인증 RPC, server_relay 차단 전용 테스트, 토큰 위조(Phase 7)
